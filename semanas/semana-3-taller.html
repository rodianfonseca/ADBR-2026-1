Taller Semana 3 — Git, GitHub y Quarto

Repositorio reproducible con datos de herpetofauna del Caribe colombiano

Autor/a

Curso 20953 · Análisis de Datos Biológicos bajo R

Fecha de publicación

22 de abril de 2026

Tipo de evidencia: Producto · Entregable: Enlace al repositorio público en GitHub · Plataforma: SICVI 567 — actividad “Taller 3”

Objetivos del taller

Al finalizar este taller, el estudiante será capaz de:

  1. Crear un repositorio público en GitHub y clonarlo como proyecto de RStudio.
  2. Construir un documento Quarto (.qmd) con YAML configurado, texto en Markdown y chunks de R con opciones #|.
  3. Cargar y explorar un dataset biológico dentro de un documento Quarto.
  4. Insertar gráficos con pie de figura (#| fig-cap:) y texto narrativo que interprete los resultados.
  5. Registrar el trabajo con al menos un commit con mensaje descriptivo y subir los cambios a GitHub con push.

Contexto biológico

La herpetofauna —reptiles y anfibios— del Caribe colombiano habita una gran diversidad de ecosistemas: manglares, ciénagas, bosques secos tropicales y zonas urbanas. Muchas de estas especies están sujetas a presiones de pérdida de hábitat y tráfico ilegal, y su monitoreo requiere reportes científicos claros, reproducibles y compartibles.

En este taller crearás un documento Quarto que analiza 60 registros de herpetofauna recolectados en los departamentos de Atlántico y Magdalena durante 2023. El documento final vivirá en un repositorio público de GitHub, lo que permite que cualquier persona —incluido el docente— pueda revisar no solo los resultados, sino el código exacto que los generó. Eso es ciencia reproducible.

Estructura esperada del repositorio

taller3-apellido-nombre/
├── taller3_apellido_nombre.qmd      ← documento Quarto principal
├── taller3_apellido_nombre.html     ← HTML renderizado (obligatorio)
├── datos/
│   └── herpetofauna_caribe_listo.csv
└── README.md                        ← descripción breve (opcional pero recomendado)

El nombre del repositorio debe seguir el patrón: taller3-apellido-nombre (minúsculas, sin tildes, guiones entre palabras).

Instrucciones paso a paso

Paso 1 — Crear el repositorio en GitHub

  1. Ve a github.com e inicia sesión.
  2. Clic en el botón verde New (esquina superior izquierda).
  3. Nombre: taller3-tuapellido-tunombre (sin tildes, sin espacios).
  4. Visibilidad: Public (obligatorio para que el docente pueda revisarlo).
  5. Marca Add a README file.
  6. Clic en Create repository.

Paso 2 — Clonar el repositorio en RStudio

  1. En tu repositorio de GitHub, clic en Code → copia la URL (HTTPS).
  2. En RStudio: File → New Project → Version Control → Git.
  3. Pega la URL en “Repository URL” → elige una carpeta local → Create Project.
  4. Verifica que aparece la pestaña Git en el panel superior derecho de RStudio.

Paso 3 — Preparar los datos

  1. Dentro de la carpeta del proyecto, crea una subcarpeta llamada datos/.
  2. Copia herpetofauna_caribe_listo.csv dentro de datos/.

Paso 4 — Crear el documento Quarto

  1. File → New File → Quarto Document.
  2. Título: “Herpetofauna del Caribe Colombiano — Análisis Exploratorio”.
  3. Author: tu nombre completo. Format: HTML. Clic en Create.
  4. Guarda como taller3_tuapellido_tunombre.qmd en la raíz del proyecto.

Paso 5 — Completar el documento

Sigue las instrucciones de las Partes 1–6 de abajo.

Paso 6 — Renderizar

Clic en el botón Render en la barra de herramientas del .qmd. Verifica que el HTML se genera sin errores y se ve bien en el navegador.

Paso 7 — Commit y Push

  1. En la pestaña Git de RStudio, marca todos los archivos (checkbox).
  2. Clic en Commit → escribe un mensaje descriptivo, por ejemplo: "Análisis exploratorio de herpetofauna completo — Taller 3"
  3. Clic en Commit, luego en Push.
  4. Verifica en github.com que los archivos aparecen en tu repositorio.

Paso 8 — Entregar en SICVI 567

Copia la URL de tu repositorio (p. ej. https://github.com/tuusuario/taller3-apellido-nombre) y pégala en el campo de entrega en SICVI 567. No subas el archivo .qmd como adjunto — solo el enlace al repositorio.

Partes del documento Quarto

Parte 1 — YAML

Configura el encabezado de tu .qmd:

---
title: "Herpetofauna del Caribe Colombiano — Análisis Exploratorio"
subtitle: "Taller Semana 3 · Curso 20953"
author: "Tu Nombre Completo"
date: "2026-04-22"
format:
  html:
    toc: true
    toc-depth: 3
    code-fold: false
    theme: cosmo
---

Usa el tema que prefieras: cosmo, flatly, lux, minty, sandstone, yeti, entre otros. Presta atención a la indentación — usa espacios, nunca tabulaciones.

Parte 2 — Introducción en Markdown

Escribe una sección ## Introducción con:

  • Un párrafo describiendo el dataset (de dónde vienen los datos, qué organismos incluye, cuántos registros tiene).
  • Una lista con al menos cuatro variables que analizarás.
  • Usa negrita, cursiva y código inline al menos una vez cada uno.

Parte 3 — Carga y exploración del dataset

Crea un chunk con #| label: cargar-datos que:

  1. Cargue el CSV: read.csv("datos/herpetofauna_caribe_listo.csv")
  2. Muestre las dimensiones: dim()
  3. Muestre los primeros registros: head()
  4. Muestre la estructura: str()

Agrega un párrafo en Markdown describiendo lo que encuentras.

Parte 4 — Gráfico 1: Registros por ecosistema

Chunk con:

  • #| label: grafico-ecosistema
  • #| fig-cap: con una descripción completa (incluye la fuente de los datos)

El gráfico debe ser un barplot de table(herp$ecosistema) con título y etiquetas en español, y al menos un color distinto al gris.

Después del chunk: párrafo que interprete el resultado.

Parte 5 — Gráfico 2: Variable morfométrica por clase

Segundo chunk con su propio #| label: y #| fig-cap:. Elige una opción:

  • boxplot() de longitud_svl_mm o peso_g agrupado por clase
  • barplot() de frecuencias por estado_uicn
  • plot() de longitud_svl_mm vs peso_g con colores por clase

Incluye párrafo de interpretación debajo del chunk.

Parte 6 — Callout de cierre

Agrega al menos un callout en el documento:

  • {.callout-note} con una observación metodológica
  • {.callout-warning} señalando una limitación del análisis
  • {.callout-tip} con una recomendación para análisis futuros

Preguntas de reflexión

Incluye las respuestas en una sección ## Reflexiones al final del documento Quarto, en prosa (no como lista de viñetas):

  1. ¿Qué ventaja tiene un documento Quarto frente a un script .R simple para comunicar resultados biológicos?
  2. Si actualizaras los datos añadiendo registros de 2024, ¿qué pasos tendría que seguir alguien para reproducir tu análisis?
  3. ¿Qué significa que un repositorio sea público en GitHub? ¿Qué implicaciones tiene para la ciencia abierta?

Errores frecuentes

Error Causa probable Solución
“cannot open file” al cargar el CSV Ruta incorrecta Verifica que el CSV esté en datos/ y la ruta sea "datos/herpetofauna_caribe_listo.csv"
“duplicate label” al renderizar Dos chunks con el mismo label Dale un nombre único a cada chunk
El HTML no aparece en GitHub No hiciste push del .html Renderiza localmente, verifica que el .html existe, luego commit + push
El repositorio es privado Olvidaste seleccionar “Public” GitHub → Settings → General → cambiar a Public
Indentación incorrecta en YAML Tabulaciones en lugar de espacios Usa solo espacios; configura en Tools → Global Options → Code
